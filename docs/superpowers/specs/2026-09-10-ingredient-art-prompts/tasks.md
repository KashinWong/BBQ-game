日期：2026-09-10。状态：T001–T005 已完成；牛肉生、熟、焦三态和三项 QA 预览已交付。T006–T023 尚未执行。

## 目标与边界

按已确认的清晰描边卡通风格，生成牛肉、青椒、蘑菇、香肠、玉米、鸡肉各自的生、熟、焦三态，共 18 张独立透明 PNG，并交付可核验的原图、整理后的素材、预览和记录。

本文件规定图片生产任务；任务勾选必须由实际文件、调用记录和验收证据支持。当前只有 T001–T005 已完成，整套生成任务完成后素材才达到可供游戏接入的状态；加载代码、图集打包、熟度贴图切换、动画特效、音乐和部署均不在此任务范围内。

## 执行约定

1. 使用 [prompts.md](./prompts.md) 对应章节的完整代码块，每次只生成或编辑一张独立图片。生成 18 张成品至少需要 18 次有效生成或编辑，返修次数另记。
2. 默认使用内置图像生成工具，并要求真实透明背景。开始时核实工具可用；如果不可用，记录实际阻塞，不把提示词、占位图或程序绘制冒充生成结果。CLI/API 备用路径遵循 imagegen 技能及用户已有授权。
3. 图片输入必须提供实际图像，文件名不能代替图片输入。内置编辑前，先将本地编辑目标加载到会话中。生牛肉无需参考图；其他生图仅以生牛肉作画风参考。
4. 熟图和焦图都从该食材同一张已选定生图独立编辑，禁止从熟图继续生成焦图。保留轮廓、锚点、尺寸、视角与光照方向。
5. 默认按编号顺序执行。牛肉三态通过 T005 自检后继续其他食材；这是素材质量检查，不增加逐张人工批准环节。每种食材的生图合格后才执行对应编辑任务。
6. 每张先生成一份候选，按验收标准选择；有明确缺陷时只针对该问题返修。保留原候选与实际提示词，不覆盖唯一原图。若某张生图被重新选定，其熟、焦两图必须重新检查；生牛肉风格改变时，另外五种生图也需复核。
7. 只有输出文件存在、完成目视检查并记录证据后才勾选生成任务。生成成功和最终素材验收通过是不同状态，T022 完成前不能宣称整套通过验收。

## 目录与记录

以下路径均相对于本 spec 目录。T001–T005 已在 candidates、selected 和 qa 中写入牛肉三态产物及记录；后续生成继续按下表保存。

| 路径 | 内容 |
| --- | --- |
| `generated/candidates/` | 每次生成的原始输出，按 `beef-raw-v01.png` 等递增版本命名 |
| `generated/selected/` | 每项任务选定的原图副本，按 `beef-raw.png` 等规范名称保存；后续编辑以这里的生图作为输入 |
| `generated/final/` | T021 统一尺寸与对齐后的 18 张交付素材，名称与 selected 一致 |
| `generated/qa/` | 对齐、原尺寸、小尺寸和不同背景的预览与检查数据 |
| `generated/generation-log.md` | 每次尝试的记录与所选版本，支持中断后继续 |

内置工具返回文件后，将项目需要的输出复制进上述目录。工具默认输出路径只作为来源记录，不作为本项目最终交付位置。对已有同名文件，先核实所属任务及版本，不直接覆盖。

每次生成在记录中填写：任务编号、食材状态、时间、所用工具及工具实际提供的模型信息、提示词章节、实际输入图片及其版本、实际提交的完整提示词、返回结果或错误、候选路径、实际尺寸与 alpha 检查结果、选定版本、返修原因。工具未提供的模型信息写“工具未返回”，不推测。

## 逐图质量标准

| 检查 | 完成条件 |
| --- | --- |
| 主体 | 单个食材单元，种类与切块形状符合提示词，不含竹签、餐具、文字、五官、烟火或拼图 |
| 画风 | 深棕描边、简单明暗、左上暖光，和选定生牛肉一致；不复制牛肉形状到其他食材 |
| 画布 | 目标 1024×1024，单件完整居中，主体最长边约占 75%，没有裁切 |
| 透明 | 实际解码确认 alpha 存在、背景确有透明像素且主体存在非透明像素；没有假棋盘格 |
| 边缘 | 在白色、#241816 和 #171412 背景上检查，无白边或明显背景残留 |
| 状态 | 生、熟、焦颜色与纹理差异清楚；焦态仍保留食材身份，不能整块纯黑 |
| 形状 | 熟、焦图保持生图朝向和轮廓，无明显新增切口、形变或缩小 |
| 小尺寸 | 在 42×36 与 34×31 显示框中等比容纳，按实际大小检查可辨认，不以放大图代替 |

若输出尺寸不符合目标，先保留原图并记录实际尺寸，再生成修正版或在 T021 中进行等比归一化；不能把不合规格的原图标记为尺寸验收通过。透明背景失败时优先针对背景返修，不把白底转成带 alpha 的白底文件当作透明图。
