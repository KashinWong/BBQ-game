# 网页六关 MVP 最终收口设计

日期：2026-08-18

## 目标

将《烤串高手》当前六关网页版本收口为可稳定试玩、可正式交付的 MVP。玩家可在主菜单或游戏暂停时调整音乐、音效和振动偏好；偏好立即生效并在后续访问中保留。现有六关进度、核心玩法和结算流程必须保持兼容。

## 需求收敛

### 已确认范围

- 在主菜单与暂停弹窗中提供设置入口，共用同一设置面板。
- 设置包含音乐、音效、振动三个独立开关，默认均开启。
- 设置切换立即生效并自动保存，不提供额外的保存按钮。
- 从暂停弹窗关闭设置后，关卡仍保持暂停，玩家须点击“继续游戏”才恢复计时和烤制。
- 当前没有背景音乐资源；音乐开关仍需正常显示和保存，作为未来背景音乐接入与微信小游戏迁移的兼容接口。
- 更新 README，使其反映六关完整 MVP、试玩方式和验证命令。
- 完成设置持久化、异常存储回退、暂停行为、六关流程与移动端竖屏验收。

### 非目标

以下内容由用户明确排除在本阶段之外：微信小游戏迁移、新玩法、美术大改、登录、云存档、排行榜、广告和养成系统。

### 成本与风险

成本带为中等：改动横跨设置存储、浏览器反馈适配器、主菜单、游戏暂停弹窗、README 与测试，但不改变订单、烤制、计分和关卡数据。主要风险是设置弹层关闭后错误恢复游戏时钟，以及浏览器本地存储不可用时阻断游玩；两者必须以自动化与竖屏交互验收覆盖。

## 架构

### 设置领域模型

新增纯 TypeScript 设置模块，暴露：

- `GameSettings`：`musicEnabled`、`soundEnabled`、`vibrationEnabled`。
- 默认值工厂，三项均为 `true`。
- 基于抽象存储端口的读取、更新与保存接口。
- 独立、带版本号的存储键，和现有关卡进度键隔离。

读取时仅接纳布尔值；缺失、损坏或不可访问的存储均回退为默认设置。保存失败静默降级，当前会话内的已选设置仍立即生效。

### 反馈适配

`BrowserFeedback` 接收设置读取接口或当前设置值：

- 音效关闭时，`play()` 不创建新的 Web Audio 节点。
- 振动关闭时，`vibrate()` 不调用浏览器振动 API。
- 音乐当前没有音频消费者，仅保存偏好；未来背景音乐接入同一设置模型。
- 音频或振动 API 不可用时保持当前静默降级行为。

### 可复用设置面板

新增一个 Phaser UI 工厂，传入场景、设置读写能力及关闭回调，返回一个可销毁的面板容器。面板不创建独立 Phaser 场景，避免处理场景叠加和返回来源。

面板行为：

- 深色遮罩与现有暖色夜市视觉一致。
- 三行固定高度的开关，每行拥有可触控的完整行区域，满足手机单指操作。
- 开关用颜色、文字状态和位置同时表达，避免只依赖颜色。
- “关闭”只销毁面板，不主动切换父界面的业务状态。

主菜单打开面板后关闭即回到菜单。暂停弹窗打开面板前已经将 `manualPaused` 设为 `true`；关闭面板后暂停弹窗仍在，只有“继续游戏”按钮能恢复。

## 影响范围

| 模块 | 改动 |
| --- | --- |
| 设置模块 | 新增设置类型、默认值、兼容读取和保存逻辑及纯单元测试。 |
| `BrowserFeedback` | 按音效与振动偏好抑制输出。 |
| 设置面板 | 新增可复用 Phaser UI 工厂。 |
| `MainMenuScene` | 增加设置入口。 |
| `GameplayScene` | 暂停弹窗增加设置入口，并保证暂停语义不变。 |
| README | 更新为六关完整 MVP 说明和本地试玩方式。 |

不修改订单生成、食材移动、烤位布局、关卡数值、积分公式和进度存储结构。

## 验收标准

1. 首次进入时三个开关均显示开启。
2. 关闭音效后，不再播放新的拾取、翻面、警告、出餐和目标提示音。
3. 关闭振动后，不再请求设备振动；浏览器不支持振动时仍可正常游玩。
4. 音乐开关显示、可切换、可持久化，但当前版本不要求播放背景音乐。
5. 刷新网页后，三个开关保留上次选择；损坏或不可用存储时回退默认值且不报错。
6. 主菜单与暂停弹窗均可打开同一设置面板。
7. 游戏暂停时调整设置、关闭面板后，倒计时、订单耐心、食材移动和烤制仍保持暂停。
8. 六个关卡可以从开始到结算连续游玩，关卡解锁和历史成绩不受设置改动影响。
9. 在 390 × 844 竖屏视口中，设置面板、暂停弹窗和关键操作区不重叠、不溢出。
10. `npm run typecheck`、`npm test` 和 `npm run build` 全部通过。

## 验证策略

- 纯单元测试：默认值、读取兼容、保存、损坏存储和单项更新。
- 反馈测试：通过可替换的浏览器 API 或决策接口验证音效与振动开关。
- 场景交互验收：主菜单入口、暂停入口、即时切换、关闭后仍暂停、刷新后持久化。
- 全局回归：六关选关、直接预览第六关、构建产物和浏览器控制台错误检查。
